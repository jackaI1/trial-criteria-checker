# Reference sample

`studies.json` is a reduced snapshot of actual ClinicalTrials.gov v2 API responses. The request URL and UTC retrieval time are inside it. Only identifiers, titles, status, update metadata and eligibility fields are kept; contact information and unrelated fields are omitted. The eligibility text is unchanged, including Markdown escapes and possible source errors. No substitute data was needed.

I selected complete criteria from the source records linked in the root README, rather than extracting only easy sentences. The set contains direct age and diagnosis requirements, nested and compound criteria, a lab with an explicit timepoint, and a lab unit that may be a source error. Recruitment is the status returned at download time.

`labels.json` was written by reading these criteria before scoring. Each nonheading criterion block has exact text offsets, inclusion/exclusion section, reference rules and a short reason. A block with no reference rules is explicitly labelled unknown for the selected scope. None of the reference rules were generated by the parser. The reference labels are development annotations, with no independent human or clinical review.

The target fields are age in years, source sex wording, explicit diagnosis terms and self-contained lab thresholds with units. A clear compound age range has reference rules for both its bounds, although the conservative parser abstains on that wording. Duration-qualified diagnoses, alternative glucose definitions, clinical judgments, treatments and functional status are outside this isolated-rule scope. The sample has no sex reference rules, and does not provide evidence for every supported lab grammar. Synthetic tests cover those code paths separately.

For each rule the scorer matches the study identifier, exact source offsets, inclusion/exclusion section and the entire rule object. Wrong values, operators, units or timing qualifiers create both an incorrect prediction and a missed reference. Unknown sentences emit no prediction; if they contain labelled rules, those rules count as misses. Duplicate predictions count as extra incorrect predictions. Undefined precision/recall is JSON null, not a fabricated perfect score.

Run `python3 -m trial_criteria benchmark` for all counts and per-field precision/recall. The output also lists every incorrect prediction and missed reference. These measurements concern parsing on a small selected development sample, not medical suitability, external validation or generalization to all trial records.

To refresh the saved source set separately:

```sh
python3 -m trial_criteria fetch --ids NCT02560883 NCT05011045 NCT07807280 NCT07524205 NCT07389005 --limit 5 --output data/refreshed.json
```

A refreshed record may have changed or stopped recruiting. Do not overwrite the benchmark snapshot without reviewing every label and source offset. Use `python3 scripts/reproduce.py` to rebuild outputs intentionally, and `--check` to detect drift without writing files.
